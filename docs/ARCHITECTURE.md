# Repository architecture

## Current executable tooling

The repository contains the metadata, source-provenance, workflow, dependency-alignment, documentation, inventory and preflight controls, plus native-tool bootstrap. The commands inspect their explicit fixed scopes and preserve source inputs. A received file cannot select a different policy or confer scientific eligibility. The foundation remains under qualification.

## Planned benchmark boundaries

| Component | Responsibility | Required evidence |
| --- | --- | --- |
| Dataset registry | Exact source bytes, licence and preprocessing | Hash-pinned admitted inputs and injective source mapping |
| Codec adapters | Invoke imported source codecs with exact effective configuration | Actual complete encode/decode and capability/refusal evidence |
| Metrics | Independent ratio, distortion and fixed single-task probe | Explicit definitions, raw populations and independent reference cases |
| Runner | Complete expected cells, timing/RSS and recovery | Actual samples, direction-specific processes and preserved attempts |
| Result assembly | Exact cell result through installed evidence provider | Real producer/consumer and complete claim inventory |
| Reports | Read-only views and scope-aware comparisons | All failed/inconclusive rows and explicit incompatibility |

The current parent registry has five binary-raster families. Waveform is a separate analogue-input capability with no public decoder in the selected class. The intended six-family population retains this gap. The native result has thirteen top-level fields; matrix completeness belongs in referenced raw populations, not an invented result member.

There are four intended benchmark CLI commands: list, run, report and compare. A separate installed-library consumer smoke exercises a real codec, complete result and independent consumer. None of these domain operations exists in this checkout yet.
