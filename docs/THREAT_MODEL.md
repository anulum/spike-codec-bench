# Data and authority boundaries

## Present tooling

The maintained checkout and explicitly selected development environment are the authority for repository controls. Received metadata, schemas, dependency receipts and generated inventories do not nominate acceptance policy. Checks reject changed identity, attribution, workflow configuration, tool or artifact selection and unsupported source paths. Diagnostics use fixed messages rather than echoing received contents.

These controls inspect bounded local scopes. Byte identity is not scientific correctness, global registration, current trust, reproducible-build proof or hosted qualification. A source inventory is not a concurrent filesystem snapshot or power-failure durability claim. Full foundation qualification remains in progress.

## Future benchmark inputs

Dataset bytes, preprocessing, event/raster mapping, compressed payloads, decoder output and evidence references are supplied data. They do not grant execution, signing, publication or device authority. Only declared local readers and selected source adapters are intended. Pickle/object input, noninjective mapping, ambiguous timebase and unknown codec capability must not silently become valid source data.

Physical measurement, process limits, cancellation/recovery, installed providers, waveform reconstruction and downstream verification remain unimplemented domain boundaries. No runtime isolation, decoder correctness, measurement accuracy or operational recovery qualification is claimed.
